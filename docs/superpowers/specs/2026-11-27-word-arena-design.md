# Word Arena — เอกสารออกแบบ (Design Spec)

วันที่: 27 พฤศจิกายน 2569
ผู้ใช้งาน: ครูญาดา กลิ่นสุคนธ์ กลุ่มสาระการเรียนรู้ภาษาต่างประเทศ โรงเรียนพระปฐมวิทยาลัย
ชื่อ "Word Arena" เป็นชื่อชั่วคราว ครูเปลี่ยนได้

---

## 1. เจตนาและเหตุผล

ครูต้องการเกมฝึกคำศัพท์ภาษาอังกฤษแบบห้องเรียนสด (คล้าย Kahoot) ให้นักเรียนเล่นพร้อมกันทั้งห้องผ่านมือถือ
คำศัพท์เป็นคำภาษาอังกฤษที่เกี่ยวกับวัฒนธรรมของห้าภาษาที่โรงเรียนสอน คือ อังกฤษ ฝรั่งเศส รัสเซีย เกาหลี และจีน
และในอนาคตครูจะเพิ่มเกมแบบอื่นลงในแพลตฟอร์มเดียวกัน

### เป้าหมาย
- ครูเปิดห้องได้ภายในไม่ถึงหนึ่งนาที นักเรียนเข้าเล่นด้วยโค้ดหรือ QR
- รองรับผู้เล่นสูงสุด 200 คนต่อห้อง รอบละ 3 นาที
- มีเกมสองแบบ คือ Guess the Word (แบบ Contexto) และ Davini (ถอดรหัส + อิโมจิ)
- เพิ่มเกมใหม่ได้โดยไม่ต้องแก้ส่วนกลาง
- ค่าใช้จ่ายเป็นศูนย์ (ใช้แผนฟรีทั้งหมด)

### ไม่ใช่เป้าหมาย (Non-goals)
- ไม่เก็บผลคะแนนถาวร ไม่ส่งออก CSV ไม่มีบัญชีผู้ใช้
- ไม่ใช่เครื่องมือวัดผลหรือเก็บข้อมูลวิจัย
- ไม่รองรับหลายห้องเป็นจำนวนมากพร้อมกันระดับเขตพื้นที่ (ใช้ระดับโรงเรียน)

### สิ่งที่ถือว่าล้มเหลวแม้ระบบจะทำงานได้ (Anti-goals)
- นักเรียนเปิด DevTools แล้วเห็นคำตอบได้
- เนื้อหาคัดลอกคำนิยามหรือประโยคจาก Cambridge/Oxford (ละเมิดลิขสิทธิ์)
- คำศัพท์ตอกย้ำภาพเหมารวมทางวัฒนธรรม (เช่น ทุกคำเกี่ยวกับรัสเซียมีแต่ vodka)
- จอโปรเจกเตอร์อ่านไม่ออกจากหลังห้อง

## 2. ข้อจำกัด

| ข้อจำกัด | ที่มา |
|---|---|
| GitHub Pages ให้บริการไฟล์ static เท่านั้น ไม่มี server | ข้อเท็จจริงของบริการ |
| Firebase แผนฟรีจำกัด 100 การเชื่อมต่อพร้อมกัน ยกเพดานไม่ได้ | เอกสาร Firebase |
| Supabase แผนฟรีจำกัด 200 การเชื่อมต่อ และ 100 ข้อความ/วินาที (ไม่พอสำหรับ 200 คน + จอครู) | เอกสาร Supabase |
| Cloudflare Workers Free: 100,000 คำขอ/วัน, CPU 10 ms/invocation (Worker), ข้อความ WebSocket ขาเข้าคิด 20:1 | เอกสาร Cloudflare |
| เนื้อหาพจนานุกรม Cambridge/Oxford มีลิขสิทธิ์ | ใช้เป็นแหล่งตรวจสอบเท่านั้น |
| เครื่องที่ใช้พัฒนาเข้า Hugging Face ไม่ได้ แต่ดาวน์โหลดโมเดล spaCy จาก GitHub ได้ | ทดสอบแล้ว 27 พ.ย. 69 |

## 3. ทางเลือกที่พิจารณา (Approaches)

| ทางเลือก | ข้อดี | ข้อเสีย | ผล |
|---|---|---|---|
| **A. GitHub Pages + Cloudflare Durable Objects** | รับ 200 คนได้ภายในแผนฟรี, WebSocket Hibernation, deploy ผ่าน GitHub Actions | ครูต้องสมัครบัญชี Cloudflare หนึ่งครั้ง | **เลือก** |
| B. GitHub Pages + Supabase Realtime | ตั้งค่าง่าย | ชนเพดาน 200 การเชื่อมต่อพอดี ต้องลดเหลือ ~150 คน | ตัดออก |
| C. เบราว์เซอร์ครูเป็น server (WebRTC/PeerJS) | ไม่ต้องสมัครบริการใด | ไม่มีหลักฐานว่ารับ 200 peer ได้, ปิดแท็บเกมหยุด, Wi-Fi โรงเรียนอาจบล็อก | ตัดออก |
| (Firebase) | — | เพดาน 100 คน | ตัดออก |

ครูเลือกทางเลือก A

## 4. สิ่งที่ครูตัดสินใจแล้ว

1. **Guess the Word** ใช้กลไกแบบ Contexto: ความใกล้วัดจาก**ความหมาย** ไม่ใช่ตัวอักษร
2. **บริบทภาษา** = คำภาษาอังกฤษที่เกี่ยวกับวัฒนธรรมของแต่ละภาษา (เช่น KIMCHI, BAGUETTE) คำตอบพิมพ์เป็นภาษาอังกฤษ
3. **Davini** ผสมรหัสและรูป: ถอดรหัสสัญลักษณ์ → ปลดล็อกอิโมจิ → พิมพ์คำตอบ
4. **รูป** ใช้อิโมจิสัญญาอนุญาตเปิด (OpenMoji, CC BY-SA 4.0) ไม่มีระบบอัปโหลดรูป
5. **คะแนน Guess the Word** เล่นเดี่ยว 1 คำต่อรอบ ทายถูกเร็วได้มาก หมดเวลาคิดจากอันดับที่ใกล้ที่สุด
6. **Davini** 1 โจทย์ยากต่อรอบ ทุกคนเล่นโจทย์เดียวกัน จบรอบครูเฉลยและอธิบายวัฒนธรรม
7. **ไม่เก็บผล** ใช้ชื่อเล่น ล้างข้อมูลเมื่อปิดห้อง
8. **คลังคำ** 100 คำ ระดับ A2–B1 แบ่ง 5 บริบท บริบทละ 20 คำ Claude ร่าง ครูตรวจก่อนนำเข้า
9. **หน้าตา** สดใสแบบเกมโชว์ ตัวอักษรใหญ่ ใช้บนโปรเจกเตอร์ได้

## 5. สถาปัตยกรรม

```
[จอครู: GitHub Pages /host]  ←WebSocket→  [Cloudflare Worker]
[มือถือนักเรียน: /play]       ←WebSocket→        │
                                                 ▼
                                   [Durable Object: Room "483920"]
                                   - รายชื่อผู้เล่น, สถานะรอบ, คะแนน
                                   - ข้อมูลคำตอบของรอบปัจจุบัน (server เท่านั้น)
```

- **หนึ่งห้อง = หนึ่ง Durable Object** ตั้งชื่อตามโค้ดห้อง 6 หลัก
- ใช้ **WebSocket Hibernation API** เพื่อลดค่า duration
- **ข้อมูลคำตอบไม่ส่งถึงเบราว์เซอร์นักเรียน** server ตรวจคำทายทุกครั้งแล้วส่งกลับเฉพาะอันดับและสี
- จอครูรับสรุปกระดานคะแนนเป็นชุด (throttle ทุก ~1 วินาที) ไม่ส่งทุกคำทาย
- นักเรียนได้รับเฉพาะผลคำทายของตัวเอง สัญญาณเริ่ม/จบรอบ และผลสรุปตอนจบ

### โครงสร้าง repo (เสนอ)
```
word-arena/
  web/                 → deploy ขึ้น GitHub Pages
    index.html         หน้าแรก (ครูสร้างห้อง / นักเรียนกรอกโค้ด)
    host.html          จอครู
    play.html          จอนักเรียน
    core/              ส่วนกลาง: การเชื่อมต่อ, lobby, timer, leaderboard, QR
    games/
      contexto/        host.js, player.js
      davini/          host.js, player.js
  server/              → deploy ขึ้น Cloudflare
    src/worker.js      router
    src/room.js        Durable Object (ส่วนกลาง)
    src/games/contexto.js, davini.js   ตรรกะฝั่ง server ของแต่ละเกม
    data/              ไฟล์ข้อมูลที่ build แล้ว (อันดับความหมาย, โจทย์)
  content/
    words.csv          คลังคำที่ครูตรวจแล้ว (แหล่งข้อมูลหลัก)
  tools/
    build_ranks.py     คำนวณอันดับความหมายด้วย spaCy
    loadtest.js        จำลองผู้เล่น 200 คน
  .github/workflows/   deploy-pages.yml, deploy-worker.yml
  docs/คู่มือครู.md
```

### สัญญาของโมดูลเกม (สำหรับเพิ่มเกมในอนาคต)
แต่ละเกมมีสามส่วน:
- `server/games/<id>.js` → `{ id, startRound(room, content), onPlayerMessage(room, player, msg), endRound(room) → results }`
- `web/games/<id>/host.js` → แสดงผลบนจอครู
- `web/games/<id>/player.js` → แสดงผลบนมือถือ

ส่วนกลางดูแล lobby, timer, การเข้า-ออก, กระดานคะแนนรวม และการเตะผู้เล่นออก

## 6. ลำดับการใช้งาน

1. ครูเปิด `/host` เลือกเกม เลือกบริบท (หรือคละ) → ระบบสร้างโค้ด 6 หลักและ QR
2. นักเรียนสแกน QR หรือกรอกโค้ด ตั้งชื่อเล่น (กรองคำหยาบ, ไม่ซ้ำในห้อง, ยาวไม่เกิน 16 ตัวอักษร)
3. จอครูแสดงจำนวนและรายชื่อผู้เล่น ครูกดเริ่ม
4. รอบละ 3 นาที (180 วินาที) นับถอยหลังบนทั้งสองจอ
5. จบรอบ → เฉลย + อธิบายบริบทวัฒนธรรม (ข้อความสั้น 1–2 ประโยค) + อันดับ 5 คนแรก
6. ครูเลือกเล่นรอบต่อไปหรือปิดห้อง ห้องที่ไม่มีการใช้งานเกิน 30 นาทีจะถูกล้างอัตโนมัติ

ผู้เล่นที่หลุดการเชื่อมต่อแล้วกลับเข้ามาด้วยชื่อเดิมจากเครื่องเดิม (token ใน sessionStorage) จะได้สถานะเดิมคืน

## 7. เกม 1: Guess the Word (Contexto)

### กลไก
- ทุกคนทายคำเป้าหมายเดียวกัน ทายได้ไม่จำกัดครั้ง
- server ตอบกลับอันดับความใกล้ เช่น `dog → #12` (อันดับ 1 = คำตอบ)
- คำที่ไม่อยู่ในคลังคำที่ทายได้ → แจ้ง "Not in word list" ไม่นับครั้ง
- จำกัดอัตราการทาย 1 ครั้งต่อ 1.5 วินาทีต่อคน (กันสแปมและคุมจำนวนคำขอ)

### สีบอกความใกล้
| อันดับ | สี | ข้อความ |
|---|---|---|
| 1 | ทอง | Correct! |
| 2–300 | เขียว | Very close |
| 301–1,500 | ส้ม | Getting warm |
| > 1,500 | แดง | Far |

เกณฑ์เหล่านี้เป็นค่าตั้งต้นของ Claude ต้องปรับหลังทดลองกับคำจริง

### คะแนน
- ทายถูก: `1000 − 3 × วินาทีที่ใช้` (ต่ำสุด 400)
- หมดเวลาโดยยังไม่ถูก: `max(0, 400 − อันดับที่ดีที่สุด ÷ 5)` ปัดเป็นจำนวนเต็ม
- จอครูแสดง "กราฟแข่งเข้าเส้นชัย" แต่ละคนเป็นจุดบนเส้นตามอันดับที่ดีที่สุด โดยไม่เปิดเผยคำที่ทาย

### การคำนวณอันดับ (ทำล่วงหน้า)
- คลังคำที่ทายได้ ≈ 15,000–20,000 คำภาษาอังกฤษทั่วไป (กรองจากคำศัพท์ใน spaCy `en_core_web_md` เอาเฉพาะตัวอักษร a–z, ตัดชื่อเฉพาะและคำหยาบ)
- สำหรับแต่ละคำเป้าหมาย: คำนวณ cosine similarity กับทุกคำ เรียงลำดับ เก็บ**อันดับทั้งหมด**เป็นไฟล์ไบนารีหรือ JSON บีบอัด ไว้ฝั่ง server
- ถ้าคำเป้าหมายใดไม่มีเวกเตอร์ หรือเพื่อนบ้าน 20 อันดับแรกดูไม่สมเหตุสมผล → ทำเครื่องหมาย `contexto=no` ใช้ใน Davini อย่างเดียว
- Claude ส่งรายงาน "20 คำที่ใกล้ที่สุด" ของทุกคำเป้าหมายให้ครูตรวจพร้อมกับตารางคำ

**ความเสี่ยงที่ต้องตรวจ:** ขนาดข้อมูลรวมต้องไม่เกินขนาด bundle ของ Worker แผนฟรี ถ้าเกิน ให้เก็บข้อมูลใน SQLite ของ Durable Object หรือเก็บเฉพาะ 5,000 อันดับแรกต่อคำ และคำที่เหลือแสดงเป็น "Far" — ผู้สร้างตัดสินจากขนาดจริง

## 8. เกม 2: Davini

### ลำดับใน 1 รอบ (1 โจทย์ยาก, 180 วินาที)
1. **ถอดรหัส**: แสดงข้อความคำใบ้ที่เข้ารหัสแบบแทนตัวอักษรด้วยสัญลักษณ์ พร้อมตารางกุญแจ*บางส่วน* (นักเรียนต้องอนุมานตัวที่เหลือ) เช่น คำใบ้ `WINTER DISH`
2. นักเรียนพิมพ์คำใบ้ที่ถอดได้ → ถูกแล้วปลดล็อก**อิโมจิ 3 ตัว** เช่น 🇰🇷 🥬 🌶️
3. **คำตอบสุดท้าย**: พิมพ์ KIMCHI

### คะแนน
- ตอบคำสุดท้ายถูกหลังปลดล็อกอิโมจิ: `1000 − 3 × วินาที` (ต่ำสุด 400)
- ข้ามขั้นถอดรหัสแล้วเดาคำสุดท้ายถูกเลย: ได้ 1.2 เท่า (เสี่ยงแต่ได้มาก)
- ทายผิด: ไม่หักคะแนน แต่จำกัดอัตรา 1 ครั้งต่อ 3 วินาที
- ถอดรหัสได้แต่ตอบคำสุดท้ายไม่ทัน: 200
- ครูอนุมัติแล้ว (27 พ.ย. 69): ข้ามขั้นถอดรหัสแล้วตอบถูกได้ 1.2 เท่า

### เนื้อหาต่อโจทย์
`answer, clue_text (≤ 3 คำ, A2–B1), emoji ×3 (OpenMoji codepoints), culture_note_en (1–2 ประโยค), culture_note_th`
ตัวสัญลักษณ์และกุญแจบางส่วนสุ่มใหม่ทุกครั้งที่เริ่มรอบ (ฝั่ง server)
**ข้อนี้ Claude ตัดสินใจเอง:** ใช้ "กุญแจบางส่วน" (เปิดให้ประมาณ 60% ของตัวอักษร) เพื่อให้โจทย์ยากพอสำหรับรอบละ 3 นาที ถ้าให้กุญแจครบ การถอดจะเป็นแค่การเทียบตาราง ใช้เวลาไม่ถึง 30 วินาที

## 9. เนื้อหา: คลังคำ 100 คำ

ไฟล์หลัก `content/words.csv` มีคอลัมน์:
`id, word, context(en|fr|ru|ko|zh), cefr(A2|B1), category, clue_text, emoji1, emoji2, emoji3, culture_note_en, culture_note_th, contexto(yes|no), teacher_approved(yes|no), dictionary_checked(cambridge|oxford|-)`

แนวทางเลือกคำ:
- บริบทละ 20 คำ คละหมวด: อาหาร เทศกาล สถานที่ ศิลปะ/ดนตรี ชีวิตประจำวันและมารยาท การทักทาย
- ต้องเป็นคำที่**มีอยู่จริงในพจนานุกรมภาษาอังกฤษ** (ครูหรือ Claude ตรวจแล้วบันทึกในคอลัมน์ `dictionary_checked`)
- คำใบ้และ culture note **เขียนใหม่ทั้งหมด** ไม่คัดลอกคำนิยามจากพจนานุกรม
- หลีกเลี่ยงคำที่ตอกย้ำภาพเหมารวม หรือคำที่มีประเด็นการเมือง/ศาสนาอ่อนไหว
- ระดับ CEFR ของ**คำใบ้**ต้องอยู่ในระดับ A2–B1 ส่วนคำเป้าหมายอาจเป็นคำยืมที่ไม่มีระดับ CEFR (เช่น kimchi) ให้ระบุ cefr ตามความยากโดยประมาณและทำเครื่องหมาย
- เฉพาะคำที่ `teacher_approved=yes` เท่านั้นที่ build เข้าเกม

## 10. หน้าตาและการใช้งาน

- สไตล์เกมโชว์สดใส: พื้นสีสด ปุ่มใหญ่ มุมโค้ง ตัวอักษรหนา
- จอครูออกแบบสำหรับโปรเจกเตอร์ 1920×1080: ตัวนับเวลาและคำเฉลยอ่านได้จากหลังห้อง (≥ 64 px), contrast ผ่าน WCAG AA
- จอนักเรียนออกแบบสำหรับมือถือก่อน (ความกว้าง 360 px): ช่องพิมพ์อยู่บน คีย์บอร์ดไม่บังผลคำทาย
- ข้อความบนจอนักเรียนเป็นภาษาอังกฤษ คู่มือครูเป็นภาษาไทย
- ไม่สื่อความหมายด้วยสีอย่างเดียว ต้องมีข้อความหรือไอคอนประกอบเสมอ (สำหรับนักเรียนที่ตาบอดสี)
- ฟอนต์: ใช้ฟอนต์ระบบหรือฟอนต์เปิดที่รองรับภาษาไทยในคู่มือ

## 11. การ deploy

- `web/` → GitHub Pages ผ่าน GitHub Actions
- `server/` → Cloudflare ผ่าน GitHub Actions (`wrangler deploy`) ใช้ `CLOUDFLARE_API_TOKEN` ใน GitHub Secrets ครูตั้งค่าเองครั้งเดียว Claude ไม่กรอก token แทน
- URL ของ Worker ตั้งค่าไว้ในไฟล์ config ของ `web/`
- คู่มือครูอธิบายทีละขั้น: สมัคร Cloudflare → สร้าง API token → ใส่ใน GitHub Secrets → push

## 12. การทดสอบและเกณฑ์การส่งมอบ

1. ทดสอบหน่วย (unit test) ตรรกะคะแนน การตรวจคำทาย และการถอดรหัสฝั่ง server
2. `tools/loadtest.js` จำลองผู้เล่น 200 คน ทายทุก 1.5–5 วินาทีตลอด 180 วินาที กับ Worker ที่ deploy จริง → ต้องไม่มีการเชื่อมต่อหลุด และวัดจำนวนคำขอจริงต่อรอบเทียบกับที่ประมาณไว้ (~600)
3. ตรวจด้วยเบราว์เซอร์: จอครูที่ 1920×1080 และมือถือที่ 360×800
4. ยืนยันว่าไม่มีคำตอบหลุดไปยังฝั่งนักเรียน (ตรวจ network และไฟล์ static ทั้งหมด)
5. **สิ่งที่ Claude ทดสอบแทนไม่ได้:** Wi-Fi และไฟร์วอลล์ของโรงเรียน ครูควรลองกับนักเรียนหนึ่งห้องก่อนใช้กับกลุ่มใหญ่

## 13. สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ
- รูปแบบไฟล์อันดับ (JSON บีบอัด / ไบนารี / SQLite) ตามขนาดจริง
- ไลบรารีสร้าง QR (ต้องทำงานฝั่ง client ไม่เรียกบริการภายนอก)
- รายการคำหยาบที่ใช้กรองชื่อเล่น
- ภาพเคลื่อนไหวและเสียงประกอบ (ต้องปิดเสียงได้)
